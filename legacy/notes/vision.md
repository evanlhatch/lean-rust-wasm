# Vision — what this is

**lean-rust-wasm is a schema-driven development toolkit whose schema
language is Lean itself.** You model an application — its data, its
functions, its state machines, its invariants, its failure modes — as
plain Lean declarations behind attributes. Elaboration is the first
gate: wrong shapes do not compile. From the elaborated registry, pure
emitters generate the Rust types, the WIT worlds, the Vortex dtypes,
the fault registries, the codecs, the docs. Every generated byte is
committed and drift-checked. The Lean semantics is the oracle: the
compiled wasm replays the same functions under wasmtime *and* wasmi
and must agree, with sabotage controls that must fail.

The target software: applications over tabular data (vortex/arrow),
deployed as WASI components with Rust hosts. The two behavioral shapes
the toolkit is built to produce natively:

- **Event sourcing** — deltas at the boundary, inversion in the log.
  A record marked event-sourced derives its change variant, journal
  codec, replay fold, and migration/upcaster lane. Schema evolution is
  replayability of the event log; the breaking gate is its checker.
- **Incremental computation (dbsp)** — queries and cascades are
  circuits over Z-sets; `incrementalize_ok` is the certificate that
  the incremental form equals batch. The theory is ported and proved;
  the emitter edge is the work.

## The correctness story, honestly layered

| Layer | Mechanism | What it buys |
|---|---|---|
| Authoring | elaboration gates (`@[schema]`, `HasCol`, type gates) | wrong shapes untypeable; errors enumerate the valid space |
| Static | kernel-checked theorems over the model | layout non-overlap, codec round-trips, machine table = step fn |
| Generative | `declare_*`/`machine!` ship proofs with the artifact | boilerplate families cannot drift |
| Build | byte-tie, one-writer audit, axiom gate, breaking gate | spec↔artifact agreement is CI, not convention |
| Runtime | the differential duel (Lean oracle vs wasmtime vs wasmi) | the compiled artifact behaves as the model |

What is NOT claimed: end-to-end compiler correctness (the wasm
backend's `emit` is partial; the cover is differential testing plus
translation-correctness slices). The honesty ledgers in
`WasmBackend/Correct.lean` and `notes/seam-contract.md` are the
record.

## The kernel

Everything loadbearing is one of seven concepts: **Universe** (closed
codes + total denotation), **Correspondence** (`Iso`/`PartialIso`/
`Denotes+ReprOp`), **Law class** (legality by instance search),
**Machine** (guarded transitions, two projections — the relational
reading included: relations are legal spec forms when they ship their
checker + bridge), **Registry→Emitter** (the buf spine), **Surface**
(attributes + macros that generate proofs), and **Obligation** (every
checkable fact as data; the enforcement tier is a computed backend
assignment). Effects cross the boundary ONE way: guest logic returns
commands as data; the host executes; results return as events.
The full analysis: `notes/lean-cohesion-plan.md`. The review:
`notes/code-review-2026-09-15.md`.

## Scope decisions (2026-09-15)

- The query frontend DSL is LATER; do not bake a concrete one into the
  schema/update layers (the dbsp circuit substrate is designed for it).
- AuthN/authZ/permissions: OUT (cedar's whole domain; a library preset
  at most, later).
- Host-side codegen (service skeletons, client stubs, mocks, command
  executors) is IN — buf generates both sides, so do we.
- Don't over-index on relational-DB shapes yet; the tabular data plane
  is vortex/arrow first.
- mathlib is a dev/tooling dep, never guest-compiled code.

## Non-goals

SIMD/cursor/pointer layer; encoding bit-structure (facts + erasure);
DataFusion internals; nanosecond anything; concurrency model-checking
(the engine is single-threaded by design). No verifier-framework deps;
patterns are owned. Proofs gate merges, never the inner loop.
