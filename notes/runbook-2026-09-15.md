# Part A — Agent primer (read first, always)

## What this repo is

lean-rust-wasm: a toolkit where Lean 4 (v4.33.0, pinned) is the schema
and behavior language for Rust/WASM applications over tabular
(vortex/arrow) data. Authors write plain Lean declarations with
attributes (`@[schema]`, `@[schema_fn]`, `schema_invariant`,
`schema_update`, `machine!`); elaboration is the first correctness
gate; pure emitter functions fold the registry into WIT/Rust/Vortex/
docs artifacts; generated artifacts are COMMITTED and drift-checked
(the byte-tie). The Lean semantics is the oracle: compiled wasm
replays the same functions under wasmtime AND wasmi and must agree.

## The concept kernel (seven concepts; everything is one of these)

1. **Universe** — closed inductive codes + a TOTAL denotation
   (`SchemaLang/Ty.lean`: `Ty` + `Ty.toType`; `VExpr` + evaluators).
2. **Correspondence** — `Iso`/`PartialIso`/`Denotes`/`ReprOp`/
   `CheckedProp` (moving to codegen-core's Kit in W1.1): every
   boundary's law lives on the shape.
3. **Law class** — legality by instance search (dbsp `Linear`,
   `ChangeSpec`, `DeltaSystem`).
4. **Machine** — guarded transitions, two projections (executable
   `step?` + relational `tr`, agreement by construction:
   Machines/Core.lean).
5. **Registry→Emitter** — env extensions collect items at
   elaboration; pure `Emitter` records (codegen-core
   `Emit/Core.lean`) fold them to files; drivers write.
6. **Surface** — attributes/macros that generate artifacts AND proofs
   (`declare_enum_wire`, `machine!`).
7. **Obligation** — every checkable fact as data with a computed
   enforcement tier (W7.1 builds this).

## Package map (lean/)

kernel (core-only, no mathlib): codegen-core, substrait, TestKit,
LintKit, proofkit. Above (mathlib available via Machines): dbsp,
Machines, schema-lang (the centerpiece), std, wasm-backend, faults,
feature-flags, ledger, qlang, edgepython. template/ = the new-project
scaffold. crates/ = Rust (forge = build driver; steel-host = wasm
host; guestlang-rt = runtime; wire = rpc).

## The gates (what "green" means)

`just gates` = lean-pkg-inventory, lean-build (all 15 packages),
gen-check (byte-tie: regenerate everything, diff must be empty),
wit-check (wit-parser round-trip), lean-axioms (no sorry/unexpected
axioms), check-schema, breaking (schema compat vs committed
snapshot), splice-smoke, rt-conformance, lean-lint. Per-package:
`cd lean/<pkg> && lake build` (+ `lake test` or
`lake exe <Pkg>Tests`).

## Hard rules (violations = reject the change)

- NEVER edit a file with the GENERATED header. Regenerate via
  `just gen` (or the package's GenMain exe).
- The boundary universe `Ty` is CLOSED: adding a constructor requires
  extending every emitter (the compiler enforces exhaustiveness —
  let it).
- Emitters are pure `spec → List GeneratedFile`; only drivers do IO.
- Zero `sorry`/`axiom`/`admit`. A missing theorem is reported, never
  stubbed.
- Module headers: ownership + deliberate exclusions + driving
  decision, ≤5 lines. No session narratives in comments.
- jj for version control: one work order = one commit;
  `jj describe -m "<WO-ID>: <what> (−N lines)"`; never git
  checkout/reset/stash.
- Style: notes/lean-doctrine.md is binding (incl. cedar-derived
  proof-style rules: `simp only` over `simp` in long proofs, `exact`
  over `apply`, anonymous hypotheses in theorem statements,
  fully-spelled types).

(e) **The killer app**: invariant-constrained row generation — ONE
